# التحكم بالبروتوكولات الحساسة للتوقيت

> **🕒 مخطَّط (غير منفَّذ بعد)** — تصميم مقترح، وقد يتغيّر قبل التنفيذ.

## لماذا لا نكتب البت-بانغ (bit-banging) بـ Lua؟
مفسّر Lua ومُجمّع القمامة يسببان تأخيرات غير متوقعة بمئات الميكروثانية، وبروتوكولات مثل DHT وWS2812 والأشعة تحت الحمراء تحتاج دقة 1 ميكروثانية.

## الفكرة: السكريبت يصف والعتاد ينفّذ
- **الإرسال:** Lua يجهز **جدول مدد النبضات**، والعتاد (RMT) يرسله بدقة.
- **الاستقبال:** العتاد يلتقط النبضات في جدول، ثم يفكّه Lua على مهل (الفك ليس حساسًا للتوقيت).

بهذا تُكتب درايفرات DHT وIR وWS2812 وغيرها **بـ Lua بدون تحديث الفيرموير**، والأجزاء التي تحتاج دقة فعلية يتولاها كود C++ ثابت داخل الفيرموير.

كل الدوال هنا **غير حاجبة**: تعطي النتيجة عبر `fn` عند الانتهاء.

## rmt — إرسال واستقبال نبضات

### `rmt.send(pin, durations [, opts] [, fn])`
يرسل نبضات. `durations` جدول مدد بالميكروثانية **متبادلة تبدأ بمستوى مرتفع** (عالٍ ثم منخفض ثم عالٍ ...).

| opts | المعنى |
|---|---|
| `idle` | مستوى الخمول بعد الإرسال (0 أو 1) |
| `carrier` | تردد حامل بالهرتز (للأشعة تحت الحمراء، مثل 38000) |
| `duty` | نسبة الحامل (افتراضي 33) |

### `rmt.receive(pin, opts, fn)`
يلتقط نبضات. `fn(durations, first_level)` عند انتهاء الإشارة.

| opts | المعنى |
|---|---|
| `timeout_ms` | أقصى انتظار (افتراضي 100) |
| `idle_us` | فجوة تعني انتهاء الإشارة (افتراضي 5000) |
| `min_us` | تجاهل النبضات الأقصر (ضجيج) |
| `pullup` | تفعيل مقاومة رفع |

### `rmt.transact(pin, tx_durations, rx_opts, fn)`
يرسل ثم يستقبل على **نفس الرجل** مباشرة (رجل واحدة ثنائية الاتجاه كـ DHT).

الحد: **512 مدة** لكل استدعاء. المتاح على C3: **قناتا إرسال وقناتا استقبال** على الجهاز كله، وهي مشتركة بين السكريبتات.

## gpio.capture — لقطة توقيت الحواف

### `gpio.capture(pin, n, fn [, edge])`
يسجل العتاد (مقاطعة بتوقيت ميكروثانية) وقت `n` حافة، ثم يستدعي `fn(timestamps)` بجدول أوقات بالميكروثانية نسبة إلى أول حافة. `edge`: `"rise"` `"fall"` `"both"` (الافتراضي).

---

## pulse — العد وقياس العرض

- `pulse.count(pin, window_ms, fn)`: يعدّ النبضات في نافذة، ثم `fn(count, hz)`. للمقاييس الدورانية وحساسات التدفق (PCNT).
- `pulse.width(pin, level, timeout_ms, fn)`: يقيس عرض نبضة بالميكروثانية؛ `fn(us)` أو `nil` عند المهلة. لحساس المسافة بالموجات فوق الصوتية وغيره.

---

## adc.sample — أخذ عينات سريعة

### `adc.sample(pin, rate_hz, n, fn)`
يجمع `n` عينة بتردد `rate_hz` (حتى 20000) بعتاد DMA، ثم `fn(samples)`. للإشارات السريعة كالصوت والاهتزاز.

## وحدات جاهزة في الفيرموير (للراحة والسرعة)

هذه يمكن كتابتها بـ Lua فوق `rmt`، لكنها مضمنة جاهزة:

| الوحدة | الدالة |
|---|---|
| `ws2812` | `ws2812.write(pin, colors [, order])`، `colors` جدول `{r,g,b}`، `order` افتراضي `"GRB"` |
| `dht` | `dht.read(pin, "DHT22", fn)` ثم `fn(temp, hum, err)` |
| `onewire` | `onewire.transaction(pin, tx_bytes, n_rx, fn)` (يتطلب توقيتًا دقيقًا فيتم في الفيرموير) |
| `ds18b20` | `ds18b20.read(pin, fn)` ثم `fn(temp)` |
| `ir` | `ir.send(pin, "nec", addr, cmd)` و`ir.receive(pin, fn)` ثم `fn(proto, addr, cmd)` |

### مثال: درايفر DHT بـ Lua فوق rmt (فكرة)

```lua
local function dht_read(pin, fn)
  rmt.transact(pin, { 18000, 40 }, { timeout_ms = 20 }, function(d, first)
    if not d then return fn(nil, nil, "timeout") end
    -- فك 40 بت من أطوال النبضات ... (الفك ليس حساسًا للتوقيت)
    fn(temp, hum)
  end)
end
```

## ملاحظات
- **السكريبتات لا تعطي توقيتًا أدق من العتاد**: أي دقة تأتي من RMT وPCNT والمقاطعات، وLua يتولى المنطق.
- إن احتجت بروتوكولًا غير مغطى، **اكتب له درايفر Lua فوق `rmt`** أولًا. وإن لم يكفِ، أخبرني وأضيف وحدة C++ جاهزة في الفيرموير (وتُنشر عبر OTA وتظهر للسكريبت كوحدة جديدة).
