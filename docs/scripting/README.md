# توثيق السكريبت (Lua)

السكريبت برنامج صغير بلغة **Lua 5.4** يعمل على الجهاز، يتحكم بأرجل ESP32-C3 ويقرأ الحساسات، ويعرض أدوات وصفحات في تبويب **🪟 اللوحات**. تكتبه وتشغّله من تبويب **🧪 مختبر Lua**.

## حالة التنفيذ

| الوحدة | الحالة | ملاحظة |
|---|---|---|
| `gpio` | ✅ | `mode` `write` `read` `toggle` `on_change` `off_change` |
| `adc` | ✅ | `read` `read_mv` (`mv`) `atten` على GPIO0–4 |
| `pwm` | ✅ | `set(pin, freq, duty%)` `duty` `stop` |
| `timer` | ✅ | `every` `after` `cancel` |
| `ui` | ✅ | أدوات جاهزة + `page/emit/on` في إطار معزول |
| `sys` / `print` / `log` | ✅ | `sys.millis` `uptime` `heap` `version` وكذلك `print` و`log` |
| `storage` | ✅ | مخزن دائم لكل سكريبت (2KB) |
| `bus` | ✅ | نشر/اشتراك بين السكريبتات |
| `i2c` | ✅ | `begin` `scan` `write` `read` `write_read` `write_reg` `read_reg` `stop` |
| `spi` `uart` | 🕒 | مخطّط |
| `rmt` `pulse` وبروتوكولات التوقيت | 🕒 | مخطّط |
| `require` والمكتبات | ✅ | `/scripts/lib/<name>.lua` |
| درايفرات موقّعة `.drv` | 🟡 | المرحلة 1 ✅ (محمّل + `lcd1602`)، جسر Lua والواجهة 🕒 — انظر drivers.md |
| `on_stop` | ✅ | تُستدعى عند الإيقاف/الاستبدال (لا عند الخطأ) |
| `--@pins` `--@needs` | 🕒 | مخطّط |

الأيقونة ✅ تعني منفَّذ ومبني في الفيرموير، و🟡 جزئي، و🕒 تصميم مقترح في الملف المعني.

## القاعدة الذهبية

**لا حلقات لا نهائية ولا انتظار.** كل شيء أحداث: مؤقتات وأزرار اللوحة. الجسم الرئيسي للسكريبت يُنفَّذ مرة واحدة للإعداد ثم تُستدعى الدوال المسجَّلة. أي استدعاء يتجاوز **200ms** يُقطع ويتوقف السكريبت بخطأ.

```lua
-- الإعداد (مرة واحدة)
gpio.mode(8, "out")

-- الأحداث
local on = false
timer.every(500, function()
  on = not on
  gpio.write(8, on)
end)
```

## دورة الحياة (الحالية)

1. **تشغيل:** يُنفَّذ الجسم مرة واحدة. أي خطأ فيه يوقف السكريبت ويظهر في الطرفية.
2. **أحداث:** تُستدعى دوال المؤقتات وأحداث اللوحات (زر، مفتاح، شريط، صفحة).
3. **إيقاف** (من المختبر أو `stop <name>`): تُستدعى الدالة العامة `on_stop()` إن وُجدت لإعادة الأرجل لحالة آمنة. ثم عند الإيقاف أو **الخطأ:** تُغلق بيئة Lua، وتُلغى المؤقتات، وتُحذف اللوحات، وتُحرَّر الأرجل وقنوات PWM.

## عدة سكريبتات

- حتى 3 سكريبتات معًا، كل منها في بيئة Lua **مستقلة**؛ انهيار أحدها لا يوقف الباقي.
- كل رجل يحجزها سكريبت واحد (يظهر خطأ `pin N owned by ...` عند التعارض).
- تشغيل سكريبت بنفس اسم سكريبت يعمل يستبدله.
- من الطرفية: `scripts` و`run <name>` (يقرأ `/scripts/<name>.lua`) و`stop <name|all>`.

## الحفظ والتشغيل التلقائي

- زر **حفظ وتشغيل** في المختبر يخزّن السكريبت كملف `/scripts/<name>.lua` على الجهاز (وصفحته المخصصة في `/ui/...` مع ملف `<name>.page` يربطهما) ثم يشغّله. تعديل سكريبت موجود: ✏️ في قائمة **السكريبتات المحفوظة** تحمّل الكود والصفحة في المحرر، ثم «حفظ وتشغيل» يستبدلانه ويعيدان التشغيل.
- علامة **تشغيل تلقائي عند إقلاع الجهاز** تكتب اسم السكريبت في `/scripts/autorun.txt`، ويُشغَّل بعد الإقلاع بنحو 2.5 ثانية (حتى 3).
- **حماية الإقلاع:** إن أُعيد تشغيل الجهاز 3 مرات متتالية خلال 30 ثانية من كل إقلاع (انهيار متكرر) تُمسح كل علامات التشغيل التلقائي وتُسجَّل رسالة في الطرفية، ويبقى الجهاز قابلًا للدخول.
- الملفات تعيش على LittleFS: **تحديث littlefs أو تنسيقه يمسحها** (النسخة الاحتياطية في تبويب «نسخ احتياطي» تشمل الإعدادات فقط).
- ⏹ يوقف السكريبت الآن فقط ولا يلغي علامة التشغيل التلقائي؛ ألغِ العلامة أو احذف السكريبت 🗑 لمنعه من العودة بعد الإقلاع.

## ما المتاح من Lua

`base` (بلا `load`/`dofile`/`loadfile`، و`require` خاصة بـ `/scripts/lib/`) و`string` (بلا `dump`) و`table` و`math` و`utf8` و`coroutine`. الأعداد الصحيحة 64 بت، والعشرية **32 بت** (لا وحدة فاصلة عائمة في C3). غير متاح: `os` و`io` و`debug`.

## الطبقات: ما في الفيرموير وما في السكريبت

- **في الفيرموير (C++):** العمليات الأساسية والتوقيت الدقيق (RMT وPCNT والمقاطعات). السكريبت يصف والعتاد ينفّذ، انظر [timing.md](timing.md). إضافة وحدة جديدة تعني تحديث الفيرموير (OTA).
- **في السكريبت (Lua):** المنطق والواجهة، ولاحقًا درايفرات I2C/SPI البسيطة فوق الدوال الأساسية.
