# ESP32-C3 WebUI

**واجهة ويب وخادم HTTP غير متزامن لبوردة ESP32-C3، مع تسجيل دخول وإعدادات واي فاي ومدير ملفات للطوارئ.**

</div>

---

## المميزات

- **خادم غير متزامن** (ESPAsyncWebServer) يقدّم واجهتك من `/app/index.html` على LittleFS.
- **تسجيل دخول بدورين:** `admin` و`user`، مع رمز (Token) يُولَّد عند كل دخول.
- **إعدادات محفوظة في JSON** على LittleFS: الواي فاي، عناوين الاتصال، رمز PIN، وكلمات المرور.
- **أوضاع واي فاي:** `AP` و`STA` و`AP_STA`. في STA تُحفظ **حتى 6 شبكات** (`/wifi_nets.json`) ويجرّبها الجهاز بحسب قوة الإشارة (10 ثوانٍ لكل شبكة)، فإن فشلت كلها انتقل إلى **وضع الاسترداد** (`RECOVERY_MODE`).
- **اسم محلي (mDNS):** من تبويب **الاتصال** حقل الاسم (مثل `esp32` فيصير `esp32.local`)، بقيود على الحروف، ويُعاد تشغيل الجهاز عند تغييره.
- **متجر التطبيقات والدرايفرات:** تبويب **درايفرات** فيه متجر تطبيقات Lua (مع صفحات HTML/canvas) ودرايفرات موقّعة (`.drv`)، بقائمة مقسّمة إلى صفحات وتثبيت تلقائي للدرايفرات الناقصة. التفاصيل في [docs/scripting/drivers.md](docs/scripting/drivers.md).
- **وضعا تنفيذ الدرايفر:** مفسّر RV32IM آمن (`vm`) أو تنفيذ أصلي على المعالج (`native`) أو تلقائي (`auto`)، يُختار من إعدادات المتجر.
- **مدير ملفات للطوارئ** على المسار `/em`: عرض، رفع، تحميل، إعادة تسمية، حذف، وتهيئة الذاكرة، مع **محرر كود** (أرقام أسطر وبحث وCtrl+S وتبويب وتكبير الخط والتفاف). صفحتا `/em` وتسجيل الدخول لها مولَّدتان مضغوطتان بـgzip في `src/em.h` من `web/em*.html` عبر `tools/gen_em.py`.
- **زر إظهار كلمة المرور** (👁) في كل حقول كلمات المرور.
- **مراقبة الموارد:** نسبة استخدام الذاكرة (RAM) والتخزين عبر `/hdusage`.

## الواجهة (Svelte)

الواجهة مكتوبة بـ Svelte + Vite في المجلد `ui/`، وتُبنى إلى ملف واحد مضغوط `data/app/index.html.gz` (بضع عشرات من الكيلوبايت).

```
cd ui
npm install
npm run build        # الناتج: data/app/index.html.gz
pio run -t uploadfs  # من جذر المشروع: رفع الواجهة إلى LittleFS
```

للتطوير مع اللوحة مباشرة: `ESP_IP=192.168.4.1 npm run dev`. أما في GitHub Actions فتُبنى الواجهة تلقائيًا ويُرفق `littlefs.bin` مع كل إصدار.

## ميزات الواجهة الإضافية

- **اللغة والمظهر:** زران عائمان (EN/ع و☀️/🌙) في صفحة الدخول وكل التبويبات وصفحة الطوارئ `/em`، ويُحفظ اختيارك في المتصفح.
- **الحالة:** إصدار البرنامج ومدة التشغيل (uptime) وزر **إعادة تشغيل الجهاز** (للـ admin).
- **نسيت كلمة المرور:** بعد 3 محاولات خاطئة (أو قفل الدخول 30 ثانية بعد 5 محاولات) يظهر الزر. يطلب الجهاز ضغط **زر فيزيائي** على الدبوس المحدد في إعداد PIN (الافتراضي GPIO9، زر BOOT) خلال 30 ثانية، وعندها تُعاد كلمات المرور إلى `admin123` و`user123` وتُقترح في حقل الدخول. من لا يملك الجهاز بيده لا يستطيع إعادة الضبط.
- **الطرفية (للـ admin):** إرسال أوامر (`help` `version` `uptime` `heap` `wifi` `ls` `df` `echo` `reboot`)، ومفتاح منزلق لعرض سجل الجهاز (Serial) مباشرة.
- **أيقونات إيموجي** للتبويبات.

## التحديث عبر الشبكة (OTA)

من الواجهة: تبويب **تحديث** (للـ admin) ثم اختر `firmware-*.bin` لتحديث البرنامج، أو `littlefs-*.bin` لتحديث الواجهة. الملفات في صفحة الإصدارات. بعد التحديث يُعاد تشغيل الجهاز تلقائيًا.

> ويمكن تحديث الواجهة أيضًا من صفحة الطوارئ `/em` (زر **تحديث الواجهة**) إذا فُقدت الواجهة.

> تحديث الواجهة (littlefs) يمسح الإعدادات وكلمات المرور. تحديث البرنامج (firmware) لا يمسحها.

المسار: `POST /api/ota?type=fw|fs` برمز admin (أو مفتاح الطوارئ لـ `type=fs` فقط) وجسم `multipart/form-data` بحقل `file`.

## النسخ الاحتياطي

تبويب **نسخ احتياطي** (للـ admin): تنزيل ملف JSON فيه الإعدادات وكلمات المرور، واستعادته لاحقًا (يُعاد تشغيل الجهاز بعدها). مفيد قبل تحديث الواجهة (littlefs) لأنه يمسح الإعدادات. المساران: `GET /settings/backup` و`POST /settings/restore`. الملف يحتوي كلمات المرور كنص صريح.

## البنية

```
platformio.ini, sdkconfig.defaults, partitions.csv
src/
  main.cpp       # الخادم والمصادقة والإعدادات والواي فاي وmDNS
  em.h           # صفحات الطوارئ (مولَّدة gzip، لا تعدّلها يدويًا)
  lua_engine.cpp # محرك Lua وجسر الدرايفرات
  drv_loader.*   # محمّل الدرايفرات الموقّعة (vm/native)
  drv_vm.*       # مفسّر RV32IM
web/             # مصدر صفحات الطوارئ
ui/              # مصدر الواجهة (Svelte)
drivers/<name>/  # مصدر الدرايفرات (C) ، drivers/build/ الناتج والفهرس
apps/            # تطبيقات المتجر (lua + json + html)
tools/           # بناء الدرايفرات والفهرس والاختبارات وgen_em.py
docs/            # التوثيق
```

## الدرايفرات والتطبيقات

13 درايفرًا (`lcd1602 ssd1306 bme280 st7789 aht20 bh1750 ds3231 ads1115 sht31 ina219 pcf8574 pca9685 mpu6050`) و18 تطبيقًا (بعضها بدرايفر وصفحة، وبعضها Lua فقط). لإضافة جديد: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md). البناء: `python3 tools/drv/build_index.py --version 1.0`، والاختبار: `python3 tools/drv/test_drivers.py` و`node tools/drv/test_store.mjs`.

## ملفات الإصدار (CI)

الـ artifact `firmware` يضم `firmware-VER.zip` (ملفات الفيرموير) و`other-VER.zip` (`drivers/` و`apps/` و`tools/`). وإصدار GitHub (وسم `v*`) يضم zip منفصلًا للفيرموير والدرايفرات والتطبيقات والأدوات والمصدر، إضافة إلى `firmware-VER.bin`.

## التشغيل

1. افتح المشروع في PlatformIO ثم نفّذ **Build** و**Upload**.
2. ابنِ الواجهة (انظر قسم الواجهة) ثم نفّذ **Upload Filesystem Image**.
3. اتصل بشبكة الـ AP الافتراضية، واسمها `ESP32_AP` وكلمة المرور `12345678`.
4. افتح `http://192.168.4.1/` للواجهة. وإذا لم يوجد `/app/index.html` (أول تشغيل أو فُقد الملف) تظهر **نافذة إدخال المفتاح السري** للدخول إلى مدير الملفات `/em`، ومنه ترفع الواجهة.

## البيانات الافتراضية

> **غيّرها قبل أي استعمال حقيقي.**

| العنصر | القيمة الافتراضية |
|---|---|
| مستخدم admin | `admin` / `admin123` |
| مستخدم user | `user` / `user123` |
| مفتاح الطوارئ `/em` | `1234` (الثابت `access_key` في `main.cpp`) |
| شبكة AP | `ESP32_AP` / `12345678` |
| شبكة الاسترداد | `RECOVERY_MODE` / `12345678` |

## واجهة البرمجة (API)

يُرسَل الرمز في الترويسة `User_Token`، ويُرسَل الدور في `User_Role` إن لزم.

| المسار | الطريقة | الصلاحية |
|---|---|---|
| `/login` | POST | عامة، جسمها `{"username","password"}` |
| `/hdusage` | GET | أي رمز صالح |
| `/settings/get_comm` ، `/settings/get_pin` | GET | أي رمز صالح |
| `/settings/get_wifi` ، `/settings/get_pass` | GET | admin |
| `/settings/get_stat` ، `/settings/scan_wifi` | GET | عامة |
| `/settings/save_wifi` ، `save_comm` ، `save_pin` ، `save_pass` | POST | admin |
| `/api/*` (مدير الملفات) | متعددة | رمز admin أو مفتاح الطوارئ |

حفظ إعدادات الواي فاي يردّ بـ `200` فورًا، ثم تُطبَّق الإعدادات بعد لحظات، وقد ينقطع الاتصال أثناء ذلك.

## ملاحظات أمنية

- نافذة المفتاح تقفل المحاولات دقيقة واحدة بعد 5 محاولات خاطئة (`/em/check`).
- مفتاح الطوارئ ما زال مقبولًا في الرابط (`?pass=`) ويُخزَّن في كوكي، فاعتبره حماية أولية فقط.
- لا تتصل بالشبكات المفتوحة وأنت تستعمل الإعدادات الافتراضية.
- الرموز لا تنتهي صلاحيتها، وكل تسجيل دخول يبطل الرمز السابق لنفس الدور.

## ⚠️ جدول الأقسام الجديد (مطلوب لمحرك Lua)

أُضيف `partitions.csv` لتكبير قسم البرنامج إلى 1.6MB. **التفليش الأول بعد هذا التغيير يكون بالكابل** (لا يمكن تغيير الأقسام عبر OTA)، بالعناوين التالية:

| الملف | العنوان |
|---|---|
| `bootloader-*.bin` | `0x0` |
| `partitions-*.bin` | `0x8000` |
| `firmware-*.bin` | `0x10000` |
| `littlefs-*.bin` | `0x350000` |

بعد ذلك يعمل OTA كالمعتاد. يمسح تفليش littlefs الإعدادات، فخذ نسخة احتياطية قبلها.

## 🧪 مختبر Lua

تبويب **مختبر Lua** يشغّل سكريبتات Lua على الجهاز (حتى 3 معًا، ذاكرة 48KB لكل سكريبت، وحارس يوقف الحلقات اللانهائية بعد 200ms). المتاح حاليًا: `gpio` و`adc` و`pwm` و`timer` و`sys` و`print`. من الطرفية: `scripts` و`run <name>` (يقرأ `/scripts/<name>.lua`) و`stop <name|all>`. تصميم الواجهة الكاملة في `docs/scripting/`.
